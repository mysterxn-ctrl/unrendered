# PLAN: Unrendered

## Grammar: 2.3 Live surface

The honest pitch is "watch what it does": the product is a pipeline that turns a sentence into a photograph. Why the other seven lost:

- Filmic one-shot, continuous world: need footage or a generated world; the brief is static, no video, no generation key.
- Chaptered editorial, typographic poster: would describe the pipeline instead of running it; the user picked "Lebendige Oberfläche".
- Gallery / catalog: no real output gallery exists yet; inventing one would break the no-fake rule.
- Split stage, rhythmic cutlist: loud cut structures, against premium-minimal.

Live-surface rules applied: app chrome instead of marketing nav (a session tab strip that is the navigation, a status line), the hero is the surface in a state, the close is an actual input. Bans held: no scrub, no kinetic, no spotlight, no drift (grounds painted per section). No 6rem headings.

## Signature move

**Scroll develops the render.** A WebGL pass applies the skill's finishing math (white balance, highlight roll-off, lens falloff, lateral chromatic aberration, sensor grain) to the brand's CGI render with strength driven by scroll, while a readout prints each live parameter. Not in the kit, not a parameter change.

## WebViSE visual skills used

- `bare_prompt_unfolds_into_growing_dual_view_console`: the close. Entry field focused, unfolds on first commit into a card per brief (ordered numeric parts: focal length, aperture, shutter, ISO, Kelvin) and an arrow per brief in one shared field (the key light's direction from a common origin, same colour identity). Persistent caveat note. Accrues, never concludes.
- `trailing_glass_magnifier_cursor`: the inspection act. Adapted: scoped to the inspected image instead of the whole view (scroll-craft refuses custom cursors), lagging lens with magnification and faint colour fringing, never blocks input, absent on touch and under reduced motion.
